# 05 · 人机协作、轨迹可视化与审计批准

## 1. 人机协作模型：三种指挥粒度

人对 Agent 的"安排"由粗到细分三档（对应 AutoGen `human_input_mode` 思想 + graph engineering 的编排粒度）：

| 粒度 | 人做什么 | 界面入口 |
| --- | --- | --- |
| **流程级**（Novice 默认） | 只在阶段门批准/打回，其余全自动 | 审批中心 |
| **任务级**（PM 日常） | 在图/看板上指派、排序、插 Gate、并行调度、批量重跑 | Graph/Board + ⌘K |
| **步级**（专家排障） | 下钻单个 Run：查看轨迹、从检查点重放、改态恢复 | Run 详情页 |

### 1.1 Graph 编排交互（任务级核心）

Graph 视图（React Flow）中，节点的可视化语法：

```
形状/角标语义：
  ▭ Phase 节点（阶段容器，折叠/展开）
  ▭ Task 节点：左上角色徽标（🤖 pm-agent / 👤 张三 / 🤖+👤 混合）
  ◆  Gate 节点（金色菱形 = 待审批，灰 = 已通过）
  ●   Run 子节点（挂在 Task 下，绿=成功 红=失败 ⏸=挂起中）
边：实线=依赖；虚线带文档图标=工件传递（hover 显示文件与版本）
状态：灰色=未就绪；蓝框=就绪待启动；蓝填充=进行中；金框=awaiting_review
```

编排操作（均产生审计事件）：

- 拖边改依赖、删边（环形依赖实时检测拒绝）；
- 指派切换：Task 在「人 / Agent 角色」间一键切换；
- 插入/删除 Gate；
- 选中多节点 → 批量「启动 Agent」「移入下个里程碑」；
- Planner-Agent 的依赖建议以**虚影边**呈现，确认后转实线（建议式 AI，决定权在人）。

### 1.2 审批策略（逐步放权）

工具三级权限 + 项目级策略（deny-by-default，借鉴 AgentScope/OpenHands）：

| 工具类别 | 示例 | 默认策略 | 可配置档位 |
| --- | --- | --- | --- |
| `read` | 读事件、读工件、查网页 | 自动放行 | 恒放行 / 记录即可 |
| `write` | 写内容仓、改工作项状态 | 白名单域内自动放行 | 每次审批 / 域内自动 / 工作时间自动 |
| `dangerous` | 建外部 PR、发通知、执行命令、外网提交 | **恒审批** | 恒审批（不可降级） |

放权路径：用户从"每次审批"逐步改为"规则自动放行"，规则 = Kanboard 三段式「**触发器 + 条件 + 动作**」（V2 规则引擎；MVP 硬编码上表默认值 + 项目设置页三个开关）。

## 2. 审批工作流

### 2.1 审批生命周期

```
Agent 运行 ──interrupt()──▶ 创建 approval(pending)
                              │
              ┌───────────────┼─────────────────┐
              ▼               ▼                 ▼
           批准(带批注)     拒绝(必填理由)     修改后恢复
              │               │                 │
        Command(resume)   Run→failed        人编辑工件/状态 →
              │               │             Command(update+resume)
              ▼               ▼                 ▼
        Run 继续         任务回流 todo        Run 带新输入继续
              └───────────────┴─────────────────┘
                     全部写入不可变审计事件
                     （含 payload 快照、reviewer、时间、批注）
```

要点：

- **fail-closed + 单次授权**（dsh 模式）：审批请求不可静默跳过（超时只提醒不放行）；`allowed-once` 语义——批准仅对该次提议生效，同类操作下次仍需授权；审批 asked/decided 均写入会话日志；
- **payload 快照**：审批对象的内容（diff、文件、拟执行命令）在请求时即快照存档，之后工件再变也不影响审计回看；
- **批量审批**：审批中心多选 → 逐条生成 `approval.granted`（借鉴 LangGraph interrupt-id→resume-map 批量恢复）；
- **超时与提醒**：pending 超过 N 小时（默认 24h）→ 通知中心提醒 + 仪表盘红点；不自动放行；
- **修改后恢复**是本方案的差异化能力：人不仅 yes/no，还能**直接修正 Agent 的输出再让它继续**（如改 PRD 一节、修 WBS 的估算），修改本身作为 `human_action` 进入轨迹。

### 2.2 阶段门（Gate）与工具审批的统一

二者是同一机制的两种触发：Gate = 图上的静态审批节点；工具审批 = Run 内动态触发的 interrupt。UI、数据模型（`approvals` 表的 `kind` 字段）、审计完全共用。

## 3. 轨迹可视化

### 3.1 四种视图，回答四个问题

| 视图 | 回答的问题 | 布局（借鉴） |
| --- | --- | --- |
| **A. 轨迹树 + 甘特瀑布** | 这一次 Run 内部结构如何？哪步慢/贵/错？ | Langfuse：左树右甘特 |
| **B. 人机交织时间线** | 人和 Agent 是怎么协作的？谁在何时介入？ | AgentOps replay 思想 + 本项目特有 |
| **C. 项目活动流** | 整个项目最近发生了什么？ | Dashboard 的轻量 feed |
| **D. Graph × Trajectory 联动** | 图上每个节点的执行史与当前进度？ | dsh Trajectory 按来源检查 + React Flow（v0.2 新增） |

### 3.2 视图 A：Run 详情（左树 + 右瀑布）

```
┌ Run: pm-agent · draft_prd ────────────── ⏸ interrupted · 3.2k tok · $0.04 ─┐
│ Span 树                    │ 甘特瀑布（时间 →）                              │
│ ▼ ● agent pm_agent         │ ████████████████████████ 24s                  │
│   ▼ ● chain analyze_req    │   ████████ 9s                                 │
│     ● ⚙ generation gpt-…   │     ███ 4s · 1.2k tok                         │
│     ● ⚙ tool read_file     │        █ 1s                                  │
│   ● ⚙ tool write_file      │             ████ 5s · diff↗                   │
│   ◆ gate prd_review        │                 ┆interrupt 21:12              │
│   ● ⏸ awaiting_human       │                  ░░░░░░░░░ (pending 2h)      │
│                                                                              
│ 选中 span 详情卡：input(折叠)/output(折叠)/attributes/错误与重试/从检查点重放↺ │
└──────────────────────────────────────────────────────────────────────────────┘
```

规则：

- 颜色编码：延迟 P95 之外的 span 橙色、error 红色、费用占比 >50% 黄色（Langfuse 瓶颈高亮）；
- 父 span 时长含子 span，UI 明示"含子项"；
- 重试显示为兄弟 span；思考文本与工具参数默认折叠，点击展开；
- 甘特区可缩放；挂起等待人的时间以浅色阴影显示，**与 Agent 执行时间视觉区分**（把"等待人"暴露出来，促进优化审批流程）。

### 3.3 视图 B：人机交织时间线（本方案特色）

纵向时间轴，交替显示双方事件（数据来源：全部事件流，不止 Run）：

```
21:03  🤖 pm-agent   生成 prd.md（run_8f3）           [查看轨迹↗]
21:05  🤖 pm-agent   请求 PRD 评审                    [审批详情↗]
21:10  👤 李雷       修改 prd.md「验收标准」节          [diff↗]
21:12  👤 李雷       批准 PRD 评审（批注：OK，补充了边界）
21:12  🤖 system     planner-agent 启动（wbs 生成）
21:18  🤖 planner    创建 12 个任务卡 · 请求计划确认    [看板预览↗]
21:25  👤 李雷       调整依赖：T7 blocked_by T3
21:26  👤 李雷       批准计划 · 批量启动 dev-agent ×5
```

价值：管理者一屏看懂"人机协作节奏"；审计者获得因果链；它同时就是**人的 trajectory**（每次人工操作都有 span 与事件）。

### 3.4 视图 C：项目活动流（Dashboard 内嵌）

最近 N 条事件的轻量 feed（图标 + 一句话 + 下钻链接），实时 SSE 更新，让新手"感觉项目在动"。

### 3.5 视图 D：Graph × Trajectory 联动（v0.2 新增，回应评审"轨迹可视化与 graph node 可视化结合"）

把**编排图（空间维度）与轨迹（时间维度）做成同一数据的两个投影并双向联动**——数据基础是"每个 span 锚定图节点"（`apm.graph_node_id`）与"对话绑定节点"：

```
Graph 视图（React Flow）                          右侧联动面板（选中节点后）
┌─────────────────────────────┐   选中     ┌──────────────────────────────┐
│ [需求intake]→(分析)→◆Gate→(计划)│ ───────▶ │ 节点: T7 导入解析 · dev-agent  │
│                └▶(T7)▶(T8)  │            │ ▸ 对话(1) ▶运行中 · 3 分钟    │
│   (T7)节点角标: 🤖1 ▶        │            │   └ 迷你时间线: ⚙write ⚙test │
│   ◆Gate角标: 🔔1 待审        │            │ ▸ 历史 Run(4) · 成功率 75%    │
└─────────────────────────────┘            │ [展开完整轨迹↗] [查看工件↗]   │
                                           └──────────────────────────────┘
```

联动规则：

1. **节点即轨迹聚合**：Task/Gate 节点角标显示绑定对话数、当前 Run 状态（▶运行/⏸挂起/🔔待审）、最近活动时间；hover 出迷你时间线（最近 Run 的 span 摘要）；
2. **点节点 → 右面板**：该节点的对话列表 + 历史 Run + 迷你甘特；点「展开完整轨迹」进入视图 A（左树右甘特）；
3. **反向跳转**：轨迹视图 A/B 中每个 span 的 `apm.graph_node_id` 可点击 → 高亮并居中图上对应节点（工件传递边随之高亮上游）；
4. **回放模式**：图上提供时间轴滑块，拖动时节点状态按历史事件回放着色（live 与 replay 共用投影函数，dsh 原则）——"上周三下午这个图长什么样"可精确重建；
5. **边 = 工件流**：produces/consumes 边点击显示该工件的版本链与消费它的下游 Run。

实现要点：span 在落库时由 Runtime 注入节点锚点（Orchestrator 启动 Run 时传入 graph_node_id）；图渲染订阅同一 SSE 流，回放用 `?at=<event_id>` 查询参数请求历史投影快照。

## 4. 审计

### 4.1 审计范围

一切 `approval.*`、`policy.changed`、`run.*` 终态、`item.status_changed`（尤其 Agent 发起）、`artifact.committed/human_edited`、`audit.exported`。

### 4.2 审计页设计

- 过滤器：时间范围 / actor（人或 Agent 角色）/ 事件类型 / 审批结果 / 项目；
- 每行：时间、actor 徽标、动作、对象链接、结果、批注；
- 行展开：事件原始 payload（JSON 折叠视图）+ 关联 span/工件 diff；
- 导出：CSV / JSONL（导出动作本身被审计）；
- 不可变保证：`events` 表触发器禁 UPDATE/DELETE；`prev_event_id` 链式校验（可选升级为哈希链）。

### 4.3 合规友好的最小集

MVP 即具备：谁（actor）、何时（ts）、对什么（agg + snapshot）、做了什么（event_type + payload）、为什么（批注 / 规则 id）。满足事后追溯与争议仲裁的基本要求；企业级合规（保留期、单独审计服务、SIEM 对接）列入 V3。

## 5. 可靠性与降级

- Agent 连续失败 N 次（默认 2）→ 自动转 `blocked` + 通知人接手（任务不悬空）；
- LLM 超时/限流 → 指数退避重试 → 仍失败按上条处理；
- 审批等待不阻塞其他分支：图中无依赖的兄弟任务照常推进（DAG 天然并行）；
- 全部中断现场可恢复：interrupt 状态 + checkpoint 双保险。
